# UR10 轨迹运动与实时曲线

## 打开与运行

推荐从工程根目录启动桌面入口：

```bash
.venv/bin/python run_yubi.py --experiment ur10_live_tracking
```

也可以普通启动后，在全局工具栏的实验下拉框选择「UR10 实时轨迹跟踪」，点击加载。加载成功后进入「验证」，点击现有的「运行」。右侧原生 MuJoCo 视口显示机器人，左侧跟踪面板显示实时曲线。

实验包含 12 秒六关节往返运动和 2 秒末端保持，在 14 秒仿真时间自动暂停并导出结果。它是一条用于观察的仿真演示轨迹，不是实机采集轨迹。真机 RTDE 与实机日志对比不包含在本次实现中。

暂停会同时停止机器人和曲线时间轴；恢复会延续当前运行段。复位恢复 home 并清除本运行段曲线，随后可以重新运行。切换模型、重新加载实验或重启后端都会生成新运行编号，避免历史曲线串入。

## 怎么看曲线

面板支持选择 J1–J6、10/30/60 秒显示窗口和 deg/rad 单位。三张默认图分别显示目标/实际位置、目标减实际的有符号误差、实际执行器关节力矩。三图共用仿真时间轴，悬停只查看读数，不暂停机器人。

数据在后端约 25 Hz 采样，现有网络桥约 20 Hz 广播。图形更新率与原始日志采样率不同；实验日志仍由独立记录器按 100 Hz 采样。面板保留最近 120 秒、最多 12000 点。

后端用同一仿真状态的独立 MjData 副本刷新执行器力矩，不修改正在运行的状态。传输携带最多 100 个带序号的近期样本，前端去重；丢失且无法恢复的样本用空白断点表示，不补出虚构读数。

## 模型与力矩来源

本实验使用 `ur10/models/ur10.xml` 的既有辨识动力学与简化摩擦参数，保留其位置伺服执行器。专用 `joint_position_servo` 插件发送关节角目标，因此这里的 `data.ctrl` 是 rad。

力矩曲线来自 `qfrc_actuator` 的关节映射，单位 N·m；包含模型的执行器力矩限制效果。该量在当前状态/控制输入处计算，表示此时模型施加的执行器力矩，不是原始位置命令。

模型中的 `damping` 和 `frictionloss` 是被动阻力。首版控制器未施加独立的摩擦前馈项，所以面板显示「摩擦补偿未接入」，不会把被动摩擦估计值或不存在的补偿显示成零。后续接入补偿控制器时，可沿固定展示接口传递实际施加的补偿项。

## 结果与故障状态

自动结果写入 `输出/实验/ur10_live_tracking_时间戳/`，包括 `states.csv`、`metrics.json`、`curves.html` 和 `experiment.json`。旧记录器的 CSV error 字段按「实际减目标」导出；本面板按「目标减实际」显示，二者符号相反，绝对误差和 RMSE 不受影响。CSV 的 ctrl 列是模型原始控制输入，本实验中单位为 rad，不能当作力矩。

运行中数据延迟超过 0.5 秒时提示更新延迟；后端断开时明确显示断开并保留最后历史。暂停或实验完成时没有新运动数据是正常行为，不会被当作故障。

## 参考实验回放对比（与实时仿真分开）

如果目标是复现 `Downloads/ur10/ur10_experiment/results/python图像` 中的六关节
电流/力矩对比图，请选择另一个实验 **「UR10 参考实验回放对比」**，而不是本页的
实时仿真实验。该实验按处理后的实机参考 q/dq 回放 3D，并在验证页显示六关节
实测/模型无摩擦/模型＋摩擦/UR 目标力矩，支持轨迹 0–9、力矩/电流、存档/重算切换。

它属于离线回放，不是实时采集，也不是正向控制复现；轨迹 1/7 的独立重算存在
接触相关差异，界面会明确标注。详见
[UR10 参考图回放界面说明](UR10参考图回放界面说明.md) 与
[UR10 参考图复现差距分析](UR10参考图复现差距分析.md)。


## 为什么「实时轨迹跟踪」和「参考实验回放」的机械臂轨迹不一样？

这是两个不同实验，机械臂不是同一套轨迹：

| 项目 | UR10 实时轨迹跟踪 | UR10 参考实验回放对比 |
|---|---|---|
| 轨迹来源 | `experiments/ur10_live_tracking.json` 里的 5 个手工航点 | `trajectory_N_identified_results.mat` 的处理后实机 `q/dq` |
| 时长 | 14 s（含 2 s 末端保持） | 约 9.02 s（轨迹 0） |
| t=0 姿态（度） | `[0, -90, 90, -90, -90, 0]`（home） | 轨迹 0 约 `[0.44, -87.28, -0.82, -90.84, -2.22, 0.63]` |
| 3 s 姿态（度） | `[17.2, -78.5, 75.6, -81.4, -78.5, 14.3]`（航点） | 轨迹 0 约 `[-31.9, -51.7, -3.7, 21.0, 23.2, 3.7]` |
| 模型/驱动 | `ur10.xml`，位置伺服 + 内置阻尼/摩擦，正向仿真 | `ur10_extfric.xml`，按存档 `q/dq` 回放，绕过正向控制 |
| 曲线含义 | 实时的目标/实际位置、跟踪误差、执行器力矩 | 存档实测电流/估算力矩 + 模型预测 + UR 目标力矩 |

两者轨迹不同不是 3D 渲染错误，也不是 1/7 接触差异导致的：参考回放按存档 q 直接回放，
实时实验仍使用旧的合成演示轨迹。若希望机器人在实时实验里也走参考轨迹，需要新增
“参考轨迹正向跟踪”的目标源（或直接用参考回放实验做演示）；当前未把两者混为一条轨迹。

参考回放的起始姿态是存档 `q(0)`，实时实验从 home 出发；这也是第一次运行时看起来
“姿态和路径都不同”的原因。
