# 内部代码命名迁移计划

本计划将内部标识符和机器接口统一为英文 ASCII，界面继续支持中文。
第一阶段交付规范、全应用盘点和防止新增问题的检查；后续阶段按依赖关系迁移实现。
历史文档中的“已迁移”有时只表示新增了英文入口，并不代表内部变量与实现已全部改完。

## 当前进度（2026-11-17）

PR #3 已合并并同步到本机，启动器缺陷已修复；具体提交与验证见 [执行记录](english-migration-execution.md)。

| 工作范围 | 当前状态 | 接下来 |
| --- | --- | --- |
| 自有 Python 代码的变量/函数/类 | 扫描标识符为 0 个非 ASCII；工具和前端测试脚本已改英文入口 | 人工核对内嵌代码和反射访问 |
| macOS/Windows 平台适配 | PR #3 收尾已合并；macOS 两个本地启动器预检通过 | Windows 新修改需在 Windows 复核 |
| 前端内部符号 | 自有变量、函数、类与类型绑定无中文；前端目录及 CSS 已英文化 | 原始消息字段集中到兼容适配层，细化动态数据结构 |
| 源码路径、CSS 与生成源码 | 前端路径、CSS 和生成器已完成；后端及项目仍有历史路径 | 整理后端/工具/控制器/项目布局及旧入口兼容 |
| 协议/配置/录制的机器键 | 仍有中文兼容字段 | 显式版本迁移并保留旧数据可读 |

下文为完整批次与验收标准；旧批次中的验证数量为当时记录，以最新执行记录为准。

## 当前事实与检查范围

- `scripts/check_naming.py` 保留原有接口边界检查，并调用新的全应用扫描。
- `scripts/audit_naming.py` 覆盖 Python、TypeScript/TSX、JavaScript、CSS、Shell 和 JSON/JSONC。
- 当前与计划中的英文源码目录都在范围内，根目录启动脚本也会被扫描。
- 前端生成源码计入清单；编译后的 `软件/web/`、依赖、字体、第三方模型、`ur10/` 外部源码和报告不计入。
- 每个解析失败都会使检查报错，不能通过跳过无法解析的文件获得“通过”。
- 中文字符串键单列为人工确认项。显示标签可以保留；机器字段、事件主题、枚举值、环境变量和持久化标识需要迁移时逐项核对。
- 嵌在字符串模板里的 JavaScript/Shell 程序、动态构造的名称和第三方 API 约束需要人工核对。HTML/XML、YAML 和模型资源文件不参与本阶段的代码标识符检查。

当前的逐文件数据见 [自动清单](naming-inventory.md)。出现次数用于定位工作量，不能换算成完成百分比。
基线通过表示没有超出已登记的问题，不表示英文化已完成。

## 第 1 批：规则、盘点与检查（本次）

交付 `naming_scope.json`、`naming_baseline.json`、扫描脚本、自动清单和 GitHub Actions 检查。
Python 使用 token 与语法树；前端使用项目固定版本的 TypeScript 编译器解析，避免把中文文案误判为变量。

验收：中文注释、文案、配置值不会导致标识符错误；新增非 ASCII 变量、模块名、目录、导入路径和 JSON 键会使增量检查失败；语法错误不能漏检。

## 第 2 批：底层适配与消息基础设施

本批前两项已完成（2026-11-16）：`official_api.py` 和 `contract.py` 的真实实现及内部调用方已迁移。
其余模块仍待逐项处理。后续同样先改内部命名，保持既有运行逻辑、参数与数据格式。

优先迁移这些仍包含实际中文实现的模块，再更新调用方：

| 旧实现 | 最终实现位置 | 同步处理 | 状态 |
| --- | --- | --- | --- |
| `官方层.py` | `official_api.py` | 延迟导入、依赖报错、官方 API 自检 | 已完成 |
| `契约.py` | `contract.py` | 内部元数据和调用方；线上字段与版本保持一致 | 已完成 |
| `命令桥.py` | `command_bridge.py` | 命令构造、校验、队列、回执 | 待处理 |
| `Web桥.py` | `web_bridge.py` | 序列化、WebSocket、主题白名单 | 待处理 |
| `界面桥.py` | `ui_bridge.py` | 目标消息、面板接口与插件调用 | 待处理 |
| `参数辨识.py` | `parameter_identification.py` | 定义、求解、结果字段 | 待处理 |

先移动实现到英文模块，再让旧入口显式转发到新模块，避免英文模块继续反向依赖旧中文模块。
兼容模块只导出已知接口，不增加同名算法副本；保留期限记入迁移说明。
Python 内部变量重命名与协议字段迁移分开提交，后者需要前后端一起更新并提供旧数据适配。

验收：英文模块持有真实实现；相关调用方不再依赖中文实现；契约自检、入口自检和前后端消息闭环通过。

契约检查 39 项、运行内核检查 4 项和六套风格资源检查通过，Panda 脚本抓取闭环通过。

契约自检 39 项、命令回执自检、运行内核与桌面启动自检均通过。

## 第 4 批：控制器和插件内部变量

## 第 5 批：平台宿主和前端内部代码

## 完成条件

1. 应用内部源码、测试和工具均使用英文 ASCII 标识符，外部平台必须保留的接口有明确记录。
2. 所有自有模块名、源码目录和导入路径为 ASCII；模型资产遵循上游目录约定并保留许可。
3. 机器配置键、消息主题、环境变量和枚举值有统一规范，旧数据迁移路径已验证。
4. 自动清单的代码和路径问题归零，字符串键人工分类完成，旧兼容入口按记录退役。
5. 严格检查和相关运行检查通过，开源文档、插件示例、打包入口均与实现一致。

## 日常命令

先安装前端锁定依赖（需要 Node 和 pnpm）；仅运行 Python/TypeScript 静态命名检查不需要启动 MuJoCo。

```bash
cd frontend
pnpm install --frozen-lockfile
cd ..
python scripts/check_naming.py
python -m unittest discover -s scripts/tests -p 'test_*.py'
python scripts/audit_naming.py --report docs/naming-inventory.md --json-report /tmp/yubi-naming-audit.json
python scripts/audit_naming.py --strict
```

`--strict` 在迁移期间预期失败，它显示剩余工作。默认检查对比现有基线，拒绝新增名称及已有名称使用次数增加。
需要增加旧接口适配时，在 PR 中说明兼容理由。基线更新必须人工审查差异；CI 不自动重建基线。
现有问题修掉后，应缩小基线，避免以后重新引入同名旧问题。

```bash
# 只在审查了当前差异后手动执行；不能用于隐藏新增问题。
python scripts/audit_naming.py --write-baseline scripts/naming_baseline.json
```
