## 1. 安装与启动

### 1.1 环境要求

| 项 | 要求 |
|---|---|
| 系统 | macOS（AppKit / WebKit）或 Windows（PySide6 / Qt WebEngine） |
| Python | macOS 实测 3.10.21；Windows 实测 3.12.7 |
| MuJoCo | 3.13.0 |
| Node.js | 运行不需要；只在修改前端时需要 |

仓库不包含 `.venv/`、`输出/` 和 `*.app/`。首次使用要重建环境。

### 1.2 重建环境

macOS：

```bash
git clone https://github.com/cyberhu-riaty/yubi.git
cd yubi
bash 工具/重建环境.sh
```

脚本会：

1. 用本机 Python 3.10 创建 `.venv`（约 190 MB）；
2. 安装 MuJoCo 3.13.0；
3. 安装 WebSocket 通信与 macOS 窗口依赖；
4. 把契约和风格表同步到前端生成物；
5. 跑一次导入自检。

Windows：

```powershell
git clone https://github.com/cyberhu-riaty/yubi.git
cd yubi
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock
```

想手工装依赖：

```bash
.venv/bin/python -m pip install -r requirements.lock
```

### 1.3 两个入口

| 入口 | 窗口 | 界面 | 3D |
|---|---|---|---|
| `软件/主程序窗口.py` | macOS AppKit / Windows Qt | 窗口内 WebView 里的 React | **嵌入式 MuJoCo 3D** |
| `软件/主程序Web.py` | 无（浏览器） | 浏览器里的 React | 无原生 3D |

```bash
# 主入口
.venv/bin/python 软件/主程序窗口.py

# 浏览器入口（同一个数据层）
.venv/bin/python 软件/主程序Web.py
```

Windows PowerShell：

```powershell
.\.venv\Scripts\python.exe .\软件\主程序窗口.py
```

两个入口共用同一套模型、项目、算法、桥和契约；差别只在「界面画在哪、3D 怎么显示」。

### 1.4 启动参数

#### 主程序窗口

| 参数 | 作用 |
|---|---|
| `--检查` | 不开窗，只检查平台层、前端产物、模型、契约和端口 |
| `--模型 <路径>` | 指定启动模型（`.xml`） |
| `--项目 <名字>` | 指定挂载哪个项目的算法组 |
| `--开重力` | 启动后就推进物理（默认冻结） |
| `--无3D` | 不建 3D 视口，只显示 Web 界面（排查用） |
| `--web口 <端口>` | Web 服务端口，默认 8712 |
| `--宽 <像素>` / `--高 <像素>` | 初始窗口尺寸 |
| `--标题 <文字>` | 窗口标题 |

#### 主程序 Web

| 参数 | 作用 |
|---|---|
| `--检查` | 不开服务，只做环境与前端产物自检 |
| `--模型 <路径>` / `--项目 <名字>` | 同主程序窗口 |
| `--开重力` | 启动后推进物理 |
| `--web口 <端口>` | 服务端口，默认 8712 |
| `--不开浏览器` | 只起服务，不自动打开浏览器 |

### 1.5 第一次启动会看到什么

普通启动先加载带地面、灯光和背景的**空场景**，不会自动恢复上次使用的机器人。
这是刻意设计：先进入工作台，再由用户从「定义 → 模型库」主动选择模型。

选择机器人后，**物理默认仍是冻结的**，模型停在默认姿态：

- 项目文件里的 `算法` 默认是空列表；
- 状态栏「仿真」显示「已暂停」；
- 要让机器人动，需要两步：**挂算法** + 点击工作台顶部的**运行**。

## 2. 界面总览

界面分四块：

```text
┌─────────────────────────────────────────────────────┐
│ 活动栏 │ 左侧上下文（任务流页面） │ 右上：3D 视口    │
│        │                          ├─────────────────│
│        │                          │ 右下：运行信息    │
├─────────────────────────────────────────────────────┤
│ 状态栏：仿真 · 仿真时间 · 实时倍率 · 指标帧率 · 连接  │
└─────────────────────────────────────────────────────┘
```

### 2.1 活动栏

十项按三组排列：

| 组 | 页面 |
|---|---|
| 流程 | 定义 → 规划 → 验证 → 辨识 → 部署 |
| 运行 | 监控 / 诊断 / 插件 |
| 信息 | 外观 / 帮助 / 关于 |

任务流只换**左侧上下文**，右侧区域常驻，不做整页跳转。Windows 默认按约 40:60 分为工作台和右列，右列再按约 70:30 分为上方 3D 与下方运行信息；两条分隔线都能拖动，并会记住最后一次比例。

### 2.2 3D 视口

- 左键拖动：旋转
- Shift + 拖动：平移
- 滚轮：缩放
- `R`：复位相机
- `F`：按模型包围盒自动取景
- 顶栏“适配视角”：与 `F` / `R` 相同，让相机重新完整对准模型
- macOS 工具栏可开关地面网格；Windows 当前先提供基础相机操作

3D 是 MuJoCo 真正渲染，不是网页里按 URDF 重算的运动学。macOS 还支持日志或规划页点击关节号后在 3D 中高亮；Windows 的网格、末端坐标和关节高亮尚未补齐。

### 2.3 Windows 运行信息

右下区域提供三个只读页签：

| 页签 | 内容 |
|---|---|
| 状态 | 仿真时间、当前模型、状态同步次数、3D 帧率 |
| 输入 | 当前 `qpos`、`qvel` 和 `ctrl`；这里只观察数据，不写控制命令 |
| 3D诊断 | 渲染帧、显示帧、同步次数、帧率和渲染错误 |

运行信息读取仿真线程传来的数值快照，不直接共享 `MjData`，因此不会改变控制器或物理步进。完整日志和系统诊断仍在左侧工作台中。

### 2.4 工作台控制台

四个页签：

| 页签 | 内容 |
|---|---|
| 输出 | 普通运行日志 |
| 事件 | 结构化事件（命令、模型切换、规划等） |
| 问题 | 警告与错误，带问题计数 |
| 诊断 | 诊断页的结果镜像 |

支持按等级、来源、插件、主题、时间筛选；可复制、导出、清空；有「跟随最新」开关。收起后仍会显示问题计数徽标。

### 2.5 状态栏

| 项 | 含义 |
|---|---|
| 仿真 | 只读运行状态。「运行中」才会推进物理；控制按钮固定在工作台顶部，它不是急停 |
| 仿真时间 | MuJoCo 的 `data.time` |
| 实时倍率 | RTF，实际推进速度 / 墙钟速度 |
| 指标帧率 | 曲线数据的实测到达速率，不是 3D 帧率 |
| 连接 | 前端与 Python 后端的 WebSocket 状态 |

### 2.6 快捷键

| 按键 | 作用 |
|---|---|
| `1`–`5` | 跳到流程第 1–5 页 |
| `` ` `` | 收起 / 展开左侧栏 |
| `[` / `]` | 调整控制台高度；按住 Shift 可大步调整 |
| `Alt` + `[` / `]` | 切换控制台页签 |
| `R` / `F` | 3D 复位 / 自动适配（焦点在 3D 时） |

输入框获得焦点时，数字键不会被当成快捷键。

## 3. 逐页说明

### 3.1 定义

这是「现在装的是哪台机器人、哪个项目」的页面。

- **当前模型**：显示名、路径、自由度 `nq`、执行器数 `nu`、状态、上次加载耗时。
- **当前项目**：项目名、算法数量、正在写 `ctrl` 的算法、输出被谁覆盖、是否已写回项目文件、兼容性报告。
- **资产库**：列出本机 `模型/模型库.json` 里的机械臂，点一下发 `换模型` 命令，等回执后生效。
- **算法库**：本机算法插件清单。
- **按路径换模型**：输入 `.xml` 路径加载未登记模型。

> 路径由后端给出，界面不拼路径。长路径只显示文件名和上级目录，完整路径在悬停提示里，可复制。

### 3.2 规划

关节空间轨迹规划。

**输入航点**

三种方式：

1. **记录当前姿态**：每点一次记一条关节航点；
2. **导入 CSV**：每行一组关节角（逗号或空格分隔），`#` 开头和首行表头会跳过；
3. **笛卡尔航点**：每行 `x y z`（米，末端世界坐标），后端用阻尼最小二乘逆解成关节航点。

**规划**

后端按真实关节限位做时间参数化，并回算校验。结果会显示：

- 航点数、自由度、总时长、路径长度；
- 终端速度（必须为 0）、最大关节速度 / 加速度 / 加加速度；
- 瓶颈（哪个关节、什么类型、在路径参数 `s` 的哪里）；
- 三项余量（1 − 实际/限位，负数表示超限）；
- 限位来源：**显式**（模型里写了）还是**估算**（界面会标出来）。

**结果处理**

- **离线产物**：轨迹会写成 `输出/05_轨迹/<项目>_<时间戳>/轨迹.csv` + `轨迹.meta.json`；
- **执行轨迹**：把轨迹当成会动的目标，复用已挂载的跟踪控制器（如关节 PD）执行；没挂控制器时不会动，可随时停止；
- **与上次对比**：只有航点相同才比较，横轴是路径参数 `s`。

> 边界：笛卡尔只支持位置，不支持姿态约束；jerk 只校验不整形；不支持圆弧/直线基本元。

### 3.3 验证

两块内容：

- **实时曲线**：最近 120 秒，横轴是墙钟（物理暂停时仿真时间不动，用仿真时间会把曲线挤成一坨）。可显示/隐藏曲线。
- **参数表**：列出各算法声明的可调参数。直接在表格里改值，回车或失焦提交，等回执后回灌最新值。

后端对一次参数提交做**事务**：全部合法才生效，任何一个越界或非法就全部回滚。

### 3.4 辨识

参数辨识页。

1. 选择可辨识参数（来自模型的惯性参数表）；
2. 点「开始辨识」，后台做闭环激励采样；
3. 显示进度、采样步数、耗时、辨识结果、拟合指标和日志；
4. 可随时停止；
5. 可导出结果。

> 辨识的验证只说明「结果比原始标称值更贴近这段数据」，**不能**说明「找到了物理真值」。界面上的残差变化百分比也只描述拟合，不给「模型更准了」的结论。

### 3.5 部署

这一页有两块：**设备控制台**与**部署包导出**。

#### 设备控制台

- 后端固定显示为「模拟后端」——它不是真机；
- 安全状态机：未连接 → 已连接（未使能）→ 使能中 → 运行；另有停止、故障、急停；
- 进入「运行」必须人工点，没有自动流程；
- 遥测：平均延迟、最大延迟、丢包、错序、被拒绝命令、最近位置；
- 劣化滑块：注入延迟、抖动、丢包、编码器量化；
- 「演练断线」：模拟链路中断，观察看门狗与安全动作；
- 「导出审计」：导出最近的操作与拒绝记录。

> 「急停」只是软件请求。真机必须有独立的物理急停回路。

#### 部署包导出

把当前项目导出到 `输出/部署/<项目名>_<时间戳>/`：

- `项目.json`：模型路径、算法列表、参数；
- `算法/`：算法源码；
- `模型清单.md`：模型文件的 SHA-256。

包里**不含模型本体**（单个资产解包可达 30 MB+），只给校验和。带到真机侧时需要自己把模型文件一起带过去。

### 3.6 监控

- 实时率 RTF、物理步频、物理步长、进程内存；
- **病态告警**：振荡、发散、跟踪超差、饱和；
- 每条告警带量化证据（频率、振幅、斜率、时间段）和走势；
- 告警建议是经验规则，不是自动整定。

> 没有检出不等于没问题，只等于没有命中这四类已知模式。

### 3.7 诊断

点「开始检查」，后端用子进程真跑 `工具/验证/` 下的 11 套脚本（该目录共 12 个脚本，延迟敏感性是单独的测量脚本，不在界面套件里）：

| 套件 | 检查什么 |
|---|---|
| 官方层 | 是否只有适配层直接 import 官方实验 API |
| 平台层 | 入口是否绕过平台适配层 |
| 契约 | 契约与 dataclass 是否漂移、前端生成物是否过期 |
| 项目 | 项目文件里的模型/算法是否真的存在且兼容 |
| 作用域 | 模块级名字是否先用后绑 |
| 语言 | 界面文案是否漏翻译、是否写死 |
| 风格表 | 皮肤颜色和样式项是否完整、是否用了会段错误的项 |
| 轨迹规划 | 轨迹内核的限位、终止速度、回算校验 |
| 参数事务 | 参数提交是否全成功或全回滚 |
| 病态检出 | 四类判定的正例/反例 |
| 设备契约 | 设备层状态机、看门狗、限幅、审计 |

结果逐项显示，失败带原因；可导出 JSON。**没有「上次全绿」缓存**，每次点都重跑。

### 3.8 插件

列出本机 `算法库/` 里的插件：

- 名称、版本、作者、说明、文件；
- 被哪些项目使用；
- 当前项目是否启用；
- 不兼容时显示装配报告里的原因，并禁止在 3D 中误以为已生效。

启用/停用只改当前项目，不下载、不安装任何东西。这里**不是**插件市场。

### 3.9 外观

- 6 套皮肤：工作台（默认）、极简、现代深色、蓝图、暖夜、航天测控；
- 点一下立即生效并记住；
- 中 / English 切换，立即生效。

### 3.10 关于

- 软件名、版本、构建方式、许可证、第三方组件；
- 后端连接状态；
- 开发信息（默认收起）：契约版本、主题数、帧号、握手、上下行主题清单。

### 3.11 帮助与按钮速查

“帮助”页只保留首次使用的最短路径；本节是完整按钮速查。界面中的按钮如果暂时不可用，通常是因为后端未连接、前置状态不满足或当前任务正在运行。把鼠标停在按钮上可以查看一句话原因。

#### 全局区域

| 按钮/区域 | 作用 | 注意事项 |
|---|---|---|
| 左侧活动栏图标 | 切换定义、规划、验证等页面 | 只切换左侧工作区，不会重置仿真 |
| 运行 | 从当前状态继续推进 MuJoCo 仿真 | 不会自动复位 |
| 暂停 | 停在当前姿态和仿真时间 | 不改变 `qpos`，也不清零 `data.time`；它不是真机急停 |
| 复位 | 恢复默认姿态并重新初始化当前算法 | 清零速度、控制量和 `data.time`，复位后保持暂停；不更换模型和算法选择 |
| 状态栏“仿真” | 显示当前运行或暂停状态 | 这里只读，避免同一功能出现两套按钮 |
| 控制台“输出 / 事件 / 问题 / 诊断” | 切换日志类型 | 收起控制台不会停止记录 |
| 复制 / 导出 | 复制或保存当前筛选后的日志 | 导出的内容受当前筛选条件影响 |
| 清空 | 清空前端日志显示 | 不会删除后端文件或仿真状态 |
| 跟随最新 | 自动滚动到最新日志 | 关闭后可停留查看旧记录 |

#### 定义、规划与验证

| 页面 | 按钮 | 作用 | 注意事项 |
|---|---|---|---|
| 定义 | 资产库中的模型 | 切换当前 MuJoCo XML | 切换会重建模型并重置仿真状态 |
| 定义 | 复制路径 | 复制完整模型或项目路径 | 长路径默认会在界面中截断 |
| 定义 | 按路径加载 | 加载模型库之外的 XML | 路径必须由后端所在计算机访问 |
| 规划 | 记录当前姿态 | 把当前 `qpos` 加为一个关节航点 | 至少记录两个航点才能规划 |
| 规划 | 规划 | 按关节限位生成时间参数化轨迹 | 速度/加速度留空时使用模型值或估算值 |
| 规划 | 清空航点 | 删除当前已记录航点 | 不会删除已经输出到磁盘的轨迹 |
| 规划 | 导入 CSV | 从 CSV/文本读取关节航点 | 每行列数必须等于当前机器人关节数 |
| 规划 | 逆解并规划 | 把 `x y z` 航点逆解为关节轨迹 | 当前只约束位置，不约束姿态 |
| 规划 | 执行轨迹 / 停止执行 | 将规划结果交给已加载控制器跟踪 | 未加载兼容控制器时模型不会按轨迹运动 |
| 规划 | 高亮瓶颈 | 在 3D 中标出瓶颈关节 | Windows 当前尚未显示关节高亮 |
| 验证 | 全选 / 全不选 | 显示或隐藏全部实时曲线 | 只影响显示，不停止数据采集 |
| 验证 | 参数单元格 | 修改插件公开的可调参数 | 回车或失焦提交；非法值会整体回滚 |

#### 辨识、部署与维护

| 页面 | 按钮 | 作用 | 注意事项 |
|---|---|---|---|
| 辨识 | 开始辨识 | 开始激励、采样和参数拟合 | 结果只说明对当前数据的拟合，不代表物理真值 |
| 辨识 | 停止 | 请求停止正在运行的辨识 | 仅在辨识运行中可用 |
| 辨识 | 导出结果 | 保存当前辨识结果 | 导出前确认本轮辨识已经结束 |
| 部署 | 导出部署包 | 导出项目、算法源码和模型校验清单 | 不包含模型本体 |
| 部署 | 打开 / 使能 / 进入运行 | 推进模拟设备状态机 | 当前是模拟后端，不是真机 |
| 部署 | 停止 | 请求模拟设备停止 | 不等同于断开设备 |
| 部署 | 急停（请求） | 发送软件急停请求 | 不能替代真机物理急停 |
| 部署 | 演练断线 | 模拟通信中断 | 用于检查看门狗和安全状态转换 |
| 部署 | 导出审计 | 保存设备操作与拒绝记录 | 只导出当前后端保存的记录 |
| 诊断 | 开始检查 | 运行本机验证脚本 | 每次都会重新执行，不使用历史缓存 |
| 诊断 | 导出 | 将本次诊断保存为 JSON | 失败项的详细原因也会写入 |
| 插件 | 启用 / 停用 | 修改当前项目加载的算法插件 | 不会下载或安装新插件；不兼容插件会被拒绝 |
| 外观 | 皮肤按钮 | 切换配色并保存偏好 | 不改变仿真数据和功能 |
| 外观 | 中文 / English | 切换网页工作台语言 | 诊断原文和部分后端日志可能保持原语言 |

## 4. 典型工作流

### A. 调一个 PD 参数

1. 定义页选一台机械臂；
2. 插件页启用「关节 PD 位置控制」；
3. 点击工作台顶部的「运行」；
4. 验证页看曲线，改 `KP` / `KD`，回车提交；
5. 观察误差收敛与振荡情况。

### B. 规划并执行一段轨迹

1. 定义页选模型，并在插件页挂一个跟踪控制器（如「关节 PD 位置控制」）；
2. 准备一份航点文件：每行一组关节角（弧度），至少两行；
3. 规划页点「导入 CSV」导入文件，或先「记录当前姿态」再补充航点；
4. 点「规划」，看总时长、终端速度、余量、瓶颈；
5. 点「执行轨迹」，在验证页看跟踪曲线；
6. 需要换约束时改速度/加速度上限，重新规划，和上次对比。

### C. 做一次参数辨识

1. 插件页启用「参数辨识」；
2. 辨识页选择参数，点「开始辨识」；
3. 等待采样和后台优化；
4. 看结果表和拟合指标；
5. 导出结果。

### D. 导出部署包

1. 定义页确认项目；
2. 部署页点「导出部署包」；
3. 在 `输出/部署/` 下查看 `项目.json`、`算法/`、`模型清单.md`；
4. 需要演练安全链路时，用设备控制台的使能、运行、断线演练和审计。

### E. 加一个自己的算法

```bash
cp 算法库/通用/我的控制律_模板.py 算法库/通用/我的算法.py
```

改类名、`名称`、`英文名`、`说明`，在 `每步控制()` 里写：

```python
@每步
def 每步控制(self, event: 插件.messages.StepEvent) -> bool:
    event.data.ctrl[:] = ...     # 6 路关节力矩
    return False
```

然后在插件页启用，或写进项目文件的 `算法` 列表。详见 README 的「扩展一个控制算法」。

## 5. 项目与模型

### 5.1 项目文件

`项目/*.json` 是「哪个模型用哪些算法、参数是多少」的唯一数据源。

```json
{
  "项目": "UR5e_基础PD",
  "模型": "模型/universal_robots_ur5e/ur5e_torque.xml",
  "算法": [{ "插件": "关节pd控制" }],
  "参数": { "关节 PD 位置控制": { "KP": 320.0 } },
  "外观": { "风格": "工作台", "主题": "light" }
}
```

- `算法` 写 `"*"`：使用算法库里的全部插件；
- 写列表：只装配列出的插件，顺序就是执行顺序；
- 写 `[]`：不挂算法；模型加载后保持静止。

项目文件里的 `算法` 默认是空列表，这是刻意的默认行为。

### 5.2 模型

| 模型 | 自由度 | 推荐文件 |
|---|---|---|
| UR5e | 6 | `ur5e_torque.xml` |
| UR10e | 6 | `ur10e_torque.xml` |
| Panda | 7 | `panda_torque.xml` |
| KUKA iiwa 14 | 7 | `iiwa14_torque.xml` |
| xArm7 | 7 | `xarm7_torque.xml` |

另有 Robotiq 2F85 夹爪资产，但它不是独立控制的机械臂模型。

**为什么必须用 `*_torque.xml`**：这些变体把执行器改成力矩输入，`ctrl` 能直接被控制插件驱动。原始模型可能执行器数不等于关节数，控制插件写 `ctrl` 会错位。

**公共场景怎么加载**：MuJoCo 仿真时最终使用一个 `MjModel`，不能让两个互不相关的 `MjModel` 同时参加同一次物理计算；但源文件可以分开维护。平台会把没有地面的纯机械臂 XML 与 `模型/公共场景.xml` 通过 `MjSpec.attach()` 组合，再编译成一个模型。机械臂 XML 本身已有平面时，则保留它自己的场景，避免叠出两个地面。

### 5.3 换模型

三种方式：

1. 定义页的资产库点选；
2. `--模型 <路径>` 启动；
3. 定义页「按路径换模型」。

换模型后，外壳先组合公共场景，再按项目文件里的 `模型` 字段反查项目，重新装配算法、重绑参数，并让仿真循环与 3D 视口同时切到新模型。最近选择仍记录在 `输出/设置.json`，供项目和界面参考；普通启动固定先进入空场景，显式传入 `--模型` 时才直接加载指定模型。

## 7. 故障排查

### macOS 窗口起不来，提示缺 PyObjC

```bash
.venv/bin/python -m pip install \
  pyobjc-framework-Cocoa pyobjc-framework-WebKit pyobjc-framework-Quartz
```

或直接用浏览器入口：

```bash
.venv/bin/python 软件/主程序Web.py
```

### Windows 窗口误用了其他 Python

先在 VS Code 选择仓库内的 `.venv\Scripts\python.exe`，再从“运行和调试”选择“Yubi Windows 主窗口（含 3D）”。在 PowerShell 中直接运行绝对路径时，路径前要加调用符号 `&`：

```powershell
& "D:\github desktop files\yubi-latest\.venv\Scripts\python.exe" "D:\github desktop files\yubi-latest\软件\主程序窗口.py"
```

### 端口 8712 被占用

```bash
.venv/bin/python 软件/主程序窗口.py --web口 8899
```

### 模型不动

按顺序排查：

1. 状态栏「仿真」是不是「已暂停」？点击工作台顶部的「运行」；
2. 当前项目有没有挂算法？插件页看启用状态；
3. 算法是否因不兼容被装配跳过？定义页看装配报告；
4. 参数是否把目标设成了当前姿态？
5. 是否开着 `--无3D`？那不影响物理，但看不到 3D。

### 插件启用了但没生效

- 看定义页的装配报告，不兼容会写明原因；
- 确认文件名不以数字开头；
- 确认 `@每步` 方法的类型标注是 `event: 插件.messages.StepEvent`；
- 确认它写的是 `event.data.ctrl[:]`，不是位置。

### 规划失败

常见原因：

- 航点太少（至少 2 条）；
- 航点超出关节限位；
- 限位来源是「估算」且过于保守；
- jerk 上限太紧（jerk 只校验，不会自动整形减速）；
- 笛卡尔点逆解不出来（会报第几个点与残差）。

### 诊断失败

诊断页会给出具体失败项和脚本输出。也可以到终端单独跑对应脚本，退出码非 0 就是失败。常见原因是改了契约没重新生成前端资产：

```bash
.venv/bin/python 工具/生成前端资产.py
```

### 3D 区域空白

- 确认 `软件/web/index.html` 和 `软件/web/assets/` 存在；
- 用 `--检查` 看前端产物；
- 重新构建前端（见下）。

### 修改前端后如何构建

```bash
cd 前端
pnpm install
pnpm run build          # 产物 → 软件/web/
cd ..
.venv/bin/python 工具/生成前端资产.py
```

Node 只在改前端时需要。构建会清空 `软件/web/`，所以不要往那里放需要长期保留的文件。

## 8. 已知边界

- **平台**：macOS 宿主功能较完整；Windows 已验证 Qt + React、MuJoCo 3D、状态同步与模型切换，但原生 3D 工具条、网格、末端坐标和关节高亮尚未补齐。Linux 宿主尚未实现。
- **真机**：没有 UDP / 串口 / CAN 后端，没有物理急停；设备层只有模拟后端。
- **规划**：只做关节空间时间参数化；笛卡尔只支持位置；jerk 只校验不整形；无圆弧/直线基本元。
- **辨识**：验证的是数据拟合，不是物理真值。
- **监控**：只覆盖振荡、发散、跟踪超差、饱和四类；没有热模型、模型失配、驱动器侧跟随误差。
- **插件**：只有本机算法库，没有远端安装。
- **3D**：没有幽灵姿态、录制回放叠加。

真机控制请把 `软件/设备/` 当接口参考，不要当安全认证组件；协议后端、硬件看门狗和物理急停必须自己实现。
