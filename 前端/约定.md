# 前端约定（P1）

> 这份文件是前端部分的**唯一约定来源**。改前端前先读它。
> 总纲见 `报告/02_决策与架构方案/驭臂重构总方案.md` 的 §3 与 §6。

## 一、目录与"谁能改什么"

```
前端/                     构建期源码（不参与运行时，可随时重建）
  src/
    生成/                 ⚠️ 生成物，**不要手改**（见下）
    数据/                 与后端的连接 + 状态仓库（P1 的 L0 层）
    外壳/                 活动栏 / 侧栏 / 中区 / 控制台 / 状态栏
    视图/                 任务流各步的视图
    组件/                 可复用小组件
  测试/                   ⚠️ 开发期工具，**不进构建产物**
    假后端.py             60 行 WebSocket 对端（按契约发帧），手动跑，用来真验界面
    界面冒烟.py           用 CDP 开一次无头 Chrome，查"真的画出来了"（截图 + 文本）
软件/web/                  ⚠️ 生成物 + 构建产物，由 Python 侧服务直接发给浏览器
```

`测试/` 那两支只在"改前端、想看一眼"时手动跑（`tsc` 证明不了"真的画出来"，
实测踩过 `useSyncExternalStore` 快照没缓存 → 整页白屏、以及中文类名 Tailwind 扫不到
这两类**只有真跑才发现**的问题）：

```bash
.venv/bin/python 前端/测试/假后端.py &            # ws + 静态产物都在 8712
.venv/bin/python 前端/测试/界面冒烟.py --输出 /tmp/冒烟
# 真后端正占着 8712 时用同一个环境变量换端口：
# env '驭臂_测试端口=8713' .venv/bin/python 前端/测试/假后端.py
# env '驭臂_测试端口=8713' .venv/bin/python 前端/测试/界面冒烟.py --输出 /tmp/冒烟
```


**生成物不要手改**（`前端/src/生成/` 与 `软件/web/assets/` 里的 `.ts`/`.css`）：

| 生成物 | 来源（单一事实来源） | 生成命令 |
|---|---|---|
| `契约.ts` | `软件/契约.py` | `./.venv/bin/python 工具/生成前端资产.py` |
| `风格.ts` | `软件/风格表.json` | 同上 |
| `主题.css` | `软件/风格表.json` | 同上 |

改了来源就跑一次生成。`工具/验证/契约自检.py` 会检查它们有没有过期。

## 二、数据怎么进来（只有这一条路）

界面**绝不**直接读文件、读进程、或调平台 API。全部通过 `前端/src/数据/仓库.ts`：

```ts
import { 用仓库, 命令, 取状态 } from "./数据/仓库";

// 只订阅自己关心的那一小块（避免整页重画）
const 项目 = 用仓库((s) => s.项目.数据);
const 曲线 = 用仓库((s) => s.曲线);

// 发命令：带校验 + 等回执，**不要"发了就算成功"**
const 回执 = await 命令.开物理(true);
if (!回执.通过) 提示(回执.说明);
```

状态分域（按域订阅，不要把整个 state 往下传 —— 那是 SPEC 点名不要抄 LE 的地方）：

| 域 | 内容 | 更新频率 |
|---|---|---|
| `项目` | 当前项目 / 算法组 / 物理开关 / 算法库 | 事件驱动 |
| `模型` | 当前模型 / 自由度 / 执行器数 | 2 Hz |
| `参数` | 各算法声明的可调参数 | 10 Hz |
| `辨识` | 参数辨识进度与结果 | 5 Hz |
| `曲线` | `{曲线名: 采样点[]}`，最近 120 秒 | 30 Hz |
| `连接` | 连接状态 / 各主题帧率 / 最近回执 | 1 Hz |

## 三、界面约定

- **换肤**：`<html data-风格="航天测控">`。全部风格与 `软件/风格表.json` 同源，
  颜色一律用 `var(--…)`，**不要写死颜色**（写死就没法换肤）。状态色另有一组
  `--ok / --warn / --danger / --info`（生成自风格表的 `网页语义色`），
  并且**颜色不单独承担信息**：状态标签必须带文字/符号。
- **双语**：界面文字走 `视图/文案.ts` 的 `取(键)`，中文与英文都在表里。
  不要在组件里硬编码中文。
- **文案不露 Markdown**：`取()` 在出口统一去掉 `**` 与反引号。文案表可以继续按
  文档习惯写强调，但画到屏幕上的必须是纯文本；需要分层的技术细节用
  “高级信息”或默认收起的“开发信息”，不要塞进首屏。
- **状态词分三层**：`后端` 是 WebSocket 进程；`真机` 是硬件（本软件未接入，固定写
  “未接入”）；`仿真` 是物理总闸（运行中/已暂停）。不要把“已连接”单独使用，
  也不要把“冻结”写成“断开”。
- **中区 3D 常驻不切换**：任务流只换**左侧上下文**，不做整页切换
  （这条是从 LE 学来的、也是它做对的地方：视图不换、只换上下文）。
  宿主窗口里 Web 只占左栏，右栏是原生 3D；Web 的中区在窄面板（≤860px）自动收起。
- **3D 视图控件**（适配/复位/网格）是宿主窗口的**原生浮层**，不经过 Web，
  也不破坏"界面数据只走仓库"的约定。
- **换模型链路**：Web `命令.换模型` → 后端 `ModelEvent` → `主程序窗口` 只把路径放进
  `视口槽["待换模型"]`（仿真线程不碰 AppKit）→ `HostApp._主线程每帧` 调
  `Viewport.换_模型()`：停旧渲染线程、重装模型、重新取景。`_模型代` 防旧装载覆盖。
- **Web / 3D 分隔条**是宿主窗口的原生 `Splitter`（7px，三个抓点）；拖拽只改
  frame 与 3D 画布，不碰业务状态。默认 40/60，Web 最小 500、3D 最小 420。
- **宿主加载 Web**：入口 URL 带版本查询串（`?v=…`），防止 WKWebView 缓存 `index.html`
  导致重新 build 后仍显示旧界面；资源缓存由构建哈希负责。
- **底部控制台**：输出 / 事件 / 问题 / 诊断四页签；日志筛选支持等级/来源/插件/主题/时间；
  有跟随/暂停自动滚动；收起后显示真实问题计数徽标。诊断页签只显示诊断结果，
  不显示日志筛选/复制/清空。
- **结构化日志**：能填才填 `模块/插件/关节`，不许从自由文本解析猜测。规划失败/估算限位
  从 `规划结果` 的真实字段生成事件；诊断失败从 `诊断报告` 的真实项生成事件。
  当前回执协议没有 `command_id`，不伪造；命令与日志通过同一次 `命令收尾` 关联。
- **关节高亮**：`命令.高亮`（视觉诊断，不改物理）；Web 发命令 → `高亮桥` 进程内状态 →
  宿主主线程读 → `Viewport.画_装饰`。前端 `J*` 徽标和规划页按钮是入口。
- **工程面板（C）**：3D 宽高比 <0.95 时只在 **3D/右列下方**出现，宽度=3D 列宽；
  左侧 Web 保持整窗高、左下角蓝色状态栏不受影响；3D 贴上边。高度
  `clamp(150, 45%×高, 高−3D宽/0.95)`。面板是**原生日志镜像**（WKScriptMessageHandler），
  不是 PTY；展开时 Web 自己的控制台通过 `data-工程面板` + CSS 收起，避免两份日志。
- **不留假数据**：任何数字要么来自 `仓库`，要么显式标成"未接入"。
  SPEC 的"假实现识别清单"是验收项，不是建议。
- **状态栏**只放运行现场：`仿真`（运行中/已暂停）· 仿真时间（`系统.仿真时间`）·
  实时倍率（`系统.RTF`）· 指标帧率（连接层实测）· `后端`（WebSocket 连接状态）。
  3D 渲染帧率留在原生工具条，物理步频留在「监控」；四个“帧率/倍率”不能混。
  项目/模型/`真机 未接入` 放到侧栏顶部的上下文条；语言开关放「外观」。
  不放行号/编码/Prettier 这类仿编辑器的装饰。

## 四、构建

```bash
# 依赖（已装）：react 19 / vite 7 / tailwind 4 / typescript 5
cd 前端
/Users/huspark/.dsh/dsh-runtimes/dsh-primary-runtime/dependencies/node/bin/node \
  /Users/huspark/.dsh/dsh-runtimes/dsh-primary-runtime/dependencies/pnpm/bin/pnpm.mjs run build
# 产物 → 软件/web/（由 Web桥 在同端口提供）
```

**★ 构建会清空 `软件/web/`**（`vite.config.ts` 里 `emptyOutDir`）。
生成物现在只落 `前端/src/生成/`，会被 Vite 打进 `软件/web/assets/`；
`软件/web/` 里不再保存第二份生成物。所以**顺序是**：

```bash
cd 前端 && <上面的构建命令>
cd .. && ./.venv/bin/python 工具/生成前端资产.py    # 保证 src/生成 与来源逐字节一致
```

第二步现在是幂等的；跑它的意义是让 `工具/验证/契约自检.py` 的"生成物是否过期"
检查通过，并保证构建用的 `src/生成/` 没有落后于 `风格表.json` / `契约.py`。

### 本机 Node 的一个坑（实测）

`pnpm` 的 shebang 是 `#!/usr/bin/env node`，所以**真正跑构建的是 PATH 里那个 node**。
本机 DSH 自带的那份 node 开了 hardened runtime（`flags=0x10000(runtime)`，Team ID
`NAN929V4UM`），它拒绝加载 rollup 的预编译原生模块（`@rollup/rollup-darwin-arm64`，
ad-hoc 签名、无 Team ID），报
`mapping process and mapped file (non-platform) have different Team IDs`。
临时把 rollup 那个 `.node` 重签成 ad-hoc 也没用，而重签 node 本身会被拒
（`internal error in Code Signing subsystem`）。所以：

```bash
# 构建：用系统 node 跑 pnpm（v24.20.0，未开 hardened runtime）
/usr/local/bin/node <pnpm.mjs 的绝对路径> run build
# 类型检查：DSH 那份 node 没问题（tsc 不加载原生模块）
```

开发时 `pnpm dev`（端口 5273）会把 `/api` 与 `/ws` 代理到 Python 侧的 8712
（注意：dev 的 WebSocket 代理在只代理 `/ws` 路径，而前端连的是 `/`，
所以冒烟测试走"假后端直接发产物"那条路，见 §一 的 `测试/`）。

**离线要求**：构建产物入库，双击启动不依赖 Node、不依赖网络。
Node 只在"改前端"时需要。
