# 二次界面评审：状态语义、岗位化文案与空状态落实

> 评审来源：工程师第二轮反馈（评分 7/10）。
> 本轮不再以“再加一块装饰”为主，而是按他给出的优先级处理：
> **① 状态语义 → ② 文案/格式 → ③ 空状态与禁用条件 → ④ 3D/布局 → ⑤ 各页工作流。**
> 结论：**合理的建议坚决改；前提不成立的建议不照做；确实受数据/架构限制的，明确写出原因。**

## 一、结论先行

这版 7/10 的主要扣分不是“3D 不够炫”，而是**界面在替用户猜**：

- “已连接”混着后端连接和真机连接；“冻结”混着暂停和断开；
- 规划页写着“未实现”，按钮却能点；辨识页写着“未接入”，按钮也能点；
- 验证页空白、部署页像开发文档、关于页把契约/话题数放在第一屏；
- 正常文案里漏出 `**`、反引号、`localStorage`、CSS 文件名、契约话题名。

这些东西不解决，3D 再漂亮也像“开发调试页”。本轮先把这些“不可信/不可读”的地方改掉。

## 三、落实情况（按主题）

### 1. 状态语义：把“一个已连接”拆成三层

- **状态栏**：`仿真 运行中/已暂停` · `仿真时间` · `实时倍率` · `指标帧率` · `后端 已连接`。
- **上下文条**：`项目` · `模型` · `真机 未接入`（虚线下划线，tooltip 明确“本软件没有真机传输层”）。
- **部署页顶部**：
  - `后端（界面数据） 已连接`
  - `真机 未接入（没有设备层）`
  - 下面才是“导出部署包”，不再让用户以为“导出=连真机”。
- **监控页**：物理暂停时 badge 是“已冻结”，不是 RTF 告警；说明“RTF 与步频为 0 是预期值”。
- **定义页**：0 算法时项目头是“兼容性未评估”，不再显示“✓ 未发现不兼容”；并给“去插件启用算法”入口。
- **规划/辨识/诊断**：
  - 规划：`尚无航点`，不是“未实现”；`规划` 在航点数 <2 时禁用，`清空` 在 0 时禁用。
  - 辨识：`尚无状态`，不是“未接入”；`停止辨识` 只在采样/辨识中可用，`开始辨识` 在断连或运行中禁用。
  - 诊断：`未运行`，不是“待接入”；`开始检查` 才可点。
- **按钮禁用视觉**：`按钮` 组件给 disabled 加 `opacity-40`，不再出现“灰字但看起来还能点”。
- **附带修复**：六处（规划/部署/监控/插件）原先把告警色写成 `var(--warning)`，但生成的主题变量叫 `var(--warn)`，所以告警文字实际上**没有颜色**。本轮全部改为 `var(--warn)`。

### 2. 文案：不再漏 Markdown，也不把开发信息塞给普通用户

- 在 `视图/文案.ts` 的 `取()` **唯一出口**统一去掉 `**` 和反引号；任何页面、`title`、日志都不会再显示原始标记。
- 重点重写：
  - 外观：不再说 `软件/风格表.json`、`生成/主题.css`、`localStorage`；主文案只说“点一下立即应用，下次打开仍会保留”。技术细节进“高级信息（开发者）”。
  - 关于：首屏只放软件名、版本、构建、许可、第三方、后端；契约/协议/主题数/帧序号/握手/上下行放进默认收起的“开发信息”。
  - 部署：不再用 `**当前项目**`、`**不连真机**` 这种文档腔；先说“导出包”，再说“真机不在范围内”。
  - 监控：不再把“系统桥”当用户词；改成“仿真进程”，并解释冻结时 0 是正常的。
  - 验证：去掉“下行主题「指标」”这种契约词，改成“后端推送的指标”；空状态给“去插件检查算法指标”。
  - 诊断：主文案只说“真跑本机检查脚本，没有缓存”；“工具/验证/、子进程”收进高级信息。
- **没有做 Markdown 渲染器**：本轮选择“在边界剥掉标记 + 重写文案”。理由：当前文案里的 `**`/反引号并没有复杂到需要富文本；剥掉后不会漏符号，也不会引入一个只服务内部文档的渲染器。若以后文案真的需要粗体/链接，再加小型渲染器。

### 3. 空状态与按钮：让“不能点”有原因

- **规划**：空状态“尚无航点”；文案“先记录至少 2 个航点，才能规划；每点一次「记录当前姿态」记一条”。按钮状态与条件一致。
- **辨识**：空状态“尚无状态”；结果/拟合空态写明“完成一次辨识后会显示什么”；开始/停止按状态禁用；新增结果 JSON 导出。
- **验证**：空图不再是一块白板——画坐标轴、轴名、网格，写“尚无指标帧”和“等待后端推送指标；或到插件检查算法是否实现指标”；下方还有“最近收到：N 秒前/尚未收到”、单位说明、去插件按钮。
- **诊断**：未运行、运行中、完成三态；运行中显示已用时；完成后逐项 ✓/✗、耗时、失败原因；可导出 JSON；高级信息单独收起。真实跑过 12/12，见证据截图。
- **部署**：导出前是“还没导出”；导出后显示真实目录、3 个文件、字节数、项目/模型/算法数量与版本；没有 SHA 字段就不在 UI 里编一个，指到包内 `模型清单.md`。
- **插件**：每张卡有“本机已安装 / 当前项目已启用或未启用”；装配报告里有不兼容时标红并禁用“启用”；没有模型要求/输入输出字段就明确写“兼容性由装配报告判定”，不猜。
- **外观**：6 套皮肤都有真实颜色预览；选中卡片用高对比底色+边框；语言区只留“中文/English”和“当前界面语言”，去掉了会让人误读的第三个“语言: English”。

### 4. 状态栏：四个“帧率/倍率”不再混

| 显示位置 | 名称 | 含义 |
|---|---|---|
| 3D 原生工具条 | `3D xx fps` | 3D 视口渲染帧率，受窗口大小/负载影响 |
| 状态栏 | `指标帧率` | 后端「指标」快照的到达频率，约 20 Hz |
| 监控页 | `物理步频` | 物理步进频率；暂停时为 0 Hz |
| 状态栏/监控 | `实时倍率 RTF` | 仿真时间推进 ÷ 真实耗时；暂停时为 0.00× |

- 3D 的 24–56 fps 与指标 20 Hz 不是一回事；本轮没有把 3D 伪装成 60 fps，也没有为了帧率降分辨率。
- 冻结时监控 badge 是“已冻结”，不再把 RTF=0 标成黄警告。

### 5. 3D / 工作区

- **可拖分隔条**：Web 与原生 3D 之间新增 7 px 原生 `Splitter`，中间有三个抓点；拖动只改两个子视图 frame 和 3D 画布，不碰业务状态。默认仍是 40/60（Web 576 / 3D 864；窗口 1440×920），但用户可以把 3D 拉大；Web 最小 500、3D 最小 420。
- **拖动分隔线时的 3D 花屏/放大已修**：用户复现的截图里机械臂突然顶满画面、网格被放大。根因是两条叠加：
  (a) `NSOpenGLView` 的 drawable 不会在 `setFrame_` 后立刻换尺寸，`glViewport` 却已经用新尺寸，
  旧 drawable 被裁切/放大；(b) 拖动期间滚轮/惯性滚动可能漏进 3D，把相机 distance 拉到 0.4 的最近值。
  修复：分隔条加宽到 7px + `acceptsFirstMouse`；拖动开始锁住 3D 相机输入并快照相机，松手恢复；
  拖动期间不重建 MuJoCo 渲染器，松手后统一重建；每次 frame 变更后 `openGLContext().update()`
  并 `displayIfNeeded()`；分隔条交互后 0.45s 内吞掉残余滚动。
- **网格**：次网格从 `(0.40,0.47,0.55)` 降到 `(0.30,0.36,0.43)`，主网格从 `(0.62,0.70,0.80)` 降到 `(0.52,0.60,0.70)`；机械臂和坐标轴仍是主体。
- **方向/尺寸图例**：3D 左下角原生浮层 `X 红 · Y 绿 · Z 蓝 · 网格 0.1m（粗线 0.5m）`，随网格步长更新。
- **构图**：首帧仿真状态到达后重新 `适配_视图`，机械臂居中；保留 1728×1692 原生画布，不靠降分辨率换帧率。
- **仍然没做**：日志横跨 Web + 3D 全宽；原因见 §五。

## 五、没改的地方，以及为什么

| 项目 | 判断 | 原因 / 下一步 |
|---|---|---|
| 底部日志横跨 Web + 3D 全宽 | 合理，但架构成本高 | 控制台是 WebView 里的 React 抽屉，只覆盖 Web 面板；要横跨原生 3D，需要第二个 WebView 或原生控制台。当前抽屉可折叠、可拖侧栏，但不会假装“全宽”。 |
| 规划的航点列表 / 关节输入 / 任务空间输入 | 合理，但契约不足 | 规划结果只回 `航点数`，没有每个航点的关节值；也没有“设置航点/任务目标”的命令。当前只支持“记录当前姿态→规划”，不能画一个假的航点表。 |
| 辨识的质量分/可信度 | 合理，但契约不足 | 后端只回状态、进度、步数、耗时、结果、拟合、日志；没有质量/置信度字段。用残差下降冒充“更准”会违反项目纪律。 |
| 部署页直接显示 SHA-256 | 合理，但契约不足 | 后端确实算 sha256 并写进 `模型清单.md`，但 `部署状态` 的清单只有文件/说明/字节，没有 hash 字段。要显示在 UI，需要契约加字段并升版本；本轮先指到包内文件。 |
| 监控趋势/阈值曲线 | 合理，但数据不足 | 「系统」每次只发瞬时值，没有历史序列；画趋势只能是假曲线。本轮只做冻结说明和 RTF 语气。 |
| 插件模型要求/输入输出/自由度 | 合理，但元数据不足 | 插件目录只有版本/说明/作者/文件/当前启用/被项目使用；没有声明适用模型或 I/O。兼容性只能等装配报告；6 轴插件挂到 7 轴时，报告会给出不兼容，本轮会把该报告标红并禁用启用。 |

## 九、追加：3D 视口随资产库实时换模型（2026-10-17）

### 现象与根因

- 现象：在「定义 → 资产库」点另一台模型，Web 卡片/项目/回执都更新了，但右侧原生 3D 仍是旧模型。
- 根因：3D 视口只在启动时从 `驭臂_当前模型` 装载一次；后端换模型成功后虽然广播了
  `ModelEvent`，但宿主窗口没有注册模型观察者，WebView 的 `模型状态` 只更新了网页，没有触达原生视口。
  这不是“命令没生效”，而是“原生视口没接这条事件”。

### 修法

- `软件/主程序窗口.py` 注册 `启动.设模型观察者`：仿真线程只把 `ModelEvent.path` 放进
  `视口槽["待换模型"]`，不碰 AppKit/GL。
- `软件/宿主窗口.py` 的 `_主线程每帧` 取走待换路径：主线程调用 `Viewport.换_模型()`。
- `换_模型()` 停旧渲染线程、清旧模型/状态缓冲/画面、按新模型重新取景、启动新渲染线程；
  用 `_模型代` 让未完成的旧装载线程作废；同一路径（含启动时的初始 ModelEvent）不重复重装。
- 结果：资产库点一下，Web 与原生 3D 在同一套真实后端状态上切换；3D 自动按新模型取景。

### 平滑处理

- **不黑屏**：重装新模型期间保留上一帧，不再先清空画面；3D 左上显示“正在切换模型：xxx”。
- **连续点击防抖**：模型事件先合并，安静 150 ms 后才真正重装；点多个模型只装最后一次，
  不会每个中间模型都停一次渲染线程。
- **失败不吞路径**：只有新模型真正装载成功才更新“当前模型路径”；加载失败保留旧模型，
  同一路径再点会重试，不会被误判成“已经是它了”。
- 重新取景仍然会发生——这是新模型尺寸/姿态不同必须做的事；现在发生在旧画面保持期间，
  新帧到达后直接切换。

### 边界

- 连续快速点多个模型时会短暂显示“正在切换模型”，最终以最后一次成功加载的模型为准。
- 手动“换模型（按路径）”走同一条 `ModelEvent`，因此也走这条重装路径。
