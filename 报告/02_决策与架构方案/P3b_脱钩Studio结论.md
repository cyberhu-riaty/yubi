# P3-b 结论：脱钩 Studio + 平台适配层

> 执行日期：2026-10-17 ｜ 前置：P3-a 宿主窗口（`P3_宿主窗口结论.md`）

## 一、先说一个**推翻了原计划**的发现

原计划写的是"`插件系统.py` 的 14 处 Studio 引用 → 指向**我们自己的消息定义**"。
实际动手前我先查了官方实现，结论是——**这条路走不通**：

```python
# endpoints.py:39-48
def send_to_sim(self, message):
    if isinstance(message, vp.Event):        ...
    elif isinstance(message, vp.Snapshot):   ...
    else: raise TypeError(f'expected Event or Snapshot, got {type(message).__name__}')

# plugin_registry.py:51-56
for message_type in type(message).__mro__:
    message_handlers.extend(self.handlers.get(message_type, []))
```

两件事决定了"自造消息类"不可行：

1. **端点做 `isinstance` 严格校验** —— 我们自造的类会被直接拒收（`TypeError`）
2. **插件派发按 `type(message).__mro__` 路由** —— 消息的**类身份**参与路由，不只是字段

> （`vp` 其实是 `messages` 的别名，见 `endpoints.py:16`。我第一版把自检写在
> `viewer_protocol` 上，立刻报了三条假警报 —— 这个错留在 `官方层.py` 的注释里当路标。）

所以只要还想保留官方那个 **19 面板窗口**（`主程序.py` 那条路），消息就必须是真的官方类。
**"彻底甩掉 Studio"等价于"官方窗口整条路都不要了"**，会丢掉 19 个现成面板 ——
与"功能一点也不能少"直接冲突。

**改用的方案**：不另造消息，而是把依赖**收敛到一处** + **启动时逐条自检**。
这才是真的降低升级风险，且不牺牲任何功能。

## 二、交付物

### 2.1 `软件/官方层.py` —— 全工程**唯一**碰官方实验层的地方

- 统一导出我们依赖的 9 个子模块 + 4 个延迟子模块（`ux` / `dear_imgui` / `implot` / `sim`）
- `自检()` 逐条核对 **26 项**：子模块在不在、`messages` 的关键符号在不在、
  端点做 `isinstance` 用的三个基类在不在、`step_control.StepControl` 在不在
- 失败时给**人话**：缺什么、当前 mujoco 版本、怎么修（而不是一串 `AttributeError`）

### 2.2 三个入口的依赖全部改道

| 范围 | 改前 | 改后 |
|---|---|---|
| 直接 import `mujoco.experimental` 的文件 | **23 个** | **1 个**（`官方层.py`） |

### 2.3 `软件/平台适配层/` —— "换一个平台最少要实现什么"

原计划要抽象四个能力。实际落地时我把它写成了**五个方法**（第四个"同级组合"在
macOS 上不需要单独的方法：两块视图加进同一个 `contentView` 就是同级，不需要额外组合步骤）：

| 能力 | 方法 |
|---|---|
| ① 建窗口 + ② 挂网页 + ④ 同级组合 | `起(地址, 标题, 宽, 高, 命令队列, 无3D, 视口槽)` |
| ③ 取视口矩形 | `视口矩形() -> (x, y, w, h) \| None` |
| 能不起得来（**起之前**就要能问） | `可用() -> (bool, str)` |
| 运行统计 | `统计() -> dict` |

**关键设计：`视口槽` 是平台层与入口之间唯一的状态通道。**
入口把"仿真每步的状态"喂给 `视口槽["视口"]`，完全不需要知道那个渲染面是什么平台的东西。

> 我一度加了两套通道（`状态回调` + `视口槽`），写完发现 `状态回调` 是死代码 ——
> 删掉了。**一个机制就够，多一个就是将来的分歧来源。**

macOS 实现 `macos.py` 是**薄委托**：真正逻辑仍在 `宿主窗口.py`（P3-a 的成果）。
不在这一层重写窗口的理由很直接：那里的坑（`NSTimer` 不触发、GL 上下文建用必须同线程、
delegate 抛异常静默失效…）都是真金白银换来的，重写等于把坑再踩一遍。

## 三、两道机器可查的不变量（这是本次最重要的一半）

抽象层只有配上断言才不会腐烂。新增两个检查：

### `工具/验证/官方层自检.py`
> 除 `软件/官方层.py` 外，`软件/` `算法库/` `工具/` 里**不允许**出现
> `import mujoco.experimental.*`（只查 import 语句，注释里提到不算）

结果：**80 个文件，0 处越界**；官方层依赖符号 **26/26**。

### `工具/验证/平台层自检.py`
> 入口文件不允许直接 import 平台模块（`宿主窗口` / `AppKit` / `WebKit` / `objc` / `Quartz`）；
> 平台实现必须覆写契约的每一个抽象方法；`起()` 必须含 `视口槽`

结果：**边界干净，契约 4/4**。

**两个检查都做了"故意违规"验证**（塞一个坏的，确认它会报，再删掉）——
不然等于没写：

```
✗ 官方层自检：软件/面板/关于面板.py:99 — 直接 from-import 了 mujoco.experimental.dear_imgui
✗ 平台层自检：主程序窗口.py:43 — 入口直接 import 了 宿主窗口，应改为经 平台适配层
```

## 五、诚实清单

| 项 | 状态 |
|---|---|
| Windows / Linux 实现 | ❌ **没有**。`平台适配层.取实现()` 会明确说"当前系统还没有窗口实现"，并指向跨平台的 `主程序Web.py` 兜底 |

| `messages` 的字段级兼容 | 未做映射层 —— 因为不需要：我们用的就是官方类，字段名天然一致 |

## 六、这一步之后，风险变成什么样

**改前**：`mujoco.experimental.studio` 的 API 一变，报错会从 **23 个文件**里冒出来，
形状多为 `AttributeError: module has no attribute 'Xxx'`，看不出该改哪。

**改后**：
- 爆炸半径 = **1 个文件**
- 启动即自检，**26 项逐条报**，缺哪个、怎么修，一句话说清
- 边界有断言盯着，不会悄悄回退

轨迹规划 → 插件市场 → 部署）。
