## 一、先说环境事实（它决定了设计）

```
toppra   ✗        ruckig  ✗        cvxpy/clarabel  ✗
numpy    ✓        scipy   ✓
```

LE 的核心管线靠 `toppra`（算速度包络）+ `ruckig`（1-DoF 时间律）。
**这两个都装不上**（本项目的规矩：不引重依赖，要能离线重建 `.venv`）。

这不只是"换个库"的问题，它**逼我们想清楚每一步到底在算什么**——而这个项目恰好
有一份逐行验算过的缺陷清单，正好逐条对照。

---

## 二、LE 的算法里，哪一半值得学、哪一半必须扔

LE 的价值在一句判断上：

> **MVC（最大可行速度）既是速度上界、又是分段判据** —— 它把"哪里需要减速"
> 从启发式规则变成了约束求解的直接产物。

这句话是对的，值得学。但它的**实现**有 13 处缺陷（§5.11），其中 4 处会直接
产生真机上不可执行的指令。所以我们的设计是：

| LE 的做法 | 我们的做法 | 为什么 |
|---|---|---|
| TOPPRA 求可行集 → 取 `X[:,1]` 当速度上界 | **直接算**：`v_s_max(s) = min_i (vlim_i / \|q_i'(s)\|)` | 只需要"速度约束下的上界"时，这是一个**闭式解**，不需要 LP/solver。TOPPRA 的完整解还含加速度约束的耦合，那部分用下面的前后向积分处理 |
| Ruckig 1-DoF 做 jerk 受限时间律 | **自己写前后向积分**（速度包络 + 加速度限 + jerk 限） | 离散网格上的前向/后向两遍扫描，逻辑 60 行，且**每一步都能解释**；比引一个 20 MB 的黑盒二进制更符合"能离线重建" |
| 回退阶梯（逐档降速重试） | **不需要**：没有"求解器报错"这种状态 | 前后向积分不会失败；不可行时是**包络本身为零**，直接报"这条路径在 s=0.43 处无法通过"，而不是退到"保持原速"假装成功 |

## 三、13 条缺陷 → 我们的对应决策（逐条）

| # | LE 缺陷 | 我们的决策 | 怎么验证 |
|---|---|---|---|
| **1** | 终止速度非零，事后**硬置零**（`:720-722`） | 后向扫描**天然**把 `s_dot` 收到 0；**绝不事后改最后一帧** | 报告 `sd[-1]`，并断言 `\|sd[-1]\| < 1e-6`；同时给出"最后 10 ms 的速度变化率" |
| **2** | `v_max` 被 `max()` 当**下限**用（`:602`） | 限位**只有上限语义**：`v_s_max` 由关节限位算出来，没有任何"下限覆盖" | 单元测试：把某关节 `vlim` 调小一半，轨迹总时长必须**变长**（若不变就是没生效） |
| **3** | s 空间限制与物理量**无换算** | **约束只在关节空间给定**（rad/s, rad/s²）；s 空间的量**每次都由链式法则现算** | 报告里同时给"用户设的关节限位"与"实际达到的最大关节量"，两者对比 |
| **4** | `qd/qdd` 用**数值微分**（`:677-678`） | **链式法则**：`qd = q'(s)·sd`，`qdd = q''(s)·sd² + q'(s)·sdd`（样条求导） | 单元测试：对一条已知解析轨迹（如正弦 s(t)），链式法则结果与解析解误差 < 1e-6 |
| **5** | 平滑后**无偏差校验**（`warnings` 恒空） | 平滑后**回算离开原始航点的最大偏差**，超过容差就**报失败并指出位置**，不静默 | 报告 `最大偏差` 与 `容差`；超了就 `成功=False` |
| **6** | 减速段**不施加 jerk 限**（`:453-454`） | **只校验、不整形**（见下方「关于 jerk 的诚实说明」） | 报告 `max\|jerk\|` 与限值对比；超限即 `成功=False` 并写明原因 |
| **7** | `ss_mode='time'` 名不符实 | 我们只有一种参数化：**按弧长**（关节空间欧氏距离）。不提供名不符实的选项 | 报告里写明用的是哪种参数化 |
| **8** | ER15/6 轴**硬编码贯穿三层** | **自由度与限位全部从 `MjModel` 读**（`jnt_range` / `jnt_limited` / 用户覆盖） | 单元测试：用 7 轴与 6 轴模型各跑一次，报告的自由度必须分别是 7 与 6 |
| **9** | TOPPRA 的时间最优解**算了丢弃** | 我们不计算它（没有 toppra）。但**报告时间最优下界**：`T_lb = ∫ ds / v_s_max(s)`，用来看我们的解离"最快"有多远 | 报告 `最优下界` vs `实际时长`，比值 < 2 说明工程实现合理 |
| **10** | 回退阶梯**只捕获 `RuntimeError`** | 设计上**没有阶梯**；任何内部异常都**向上抛并带上下文**（哪一段、哪个 s） | 单元测试：构造一条不可行路径，必须抛/报明确原因，不能静默返回轨迹 |
| **11** | `segment_points` 与 `segment_targets` **两种表示** | 只有**一份**网格 `s[i]`；所有量都挂在它上面 | 代码中不出现第二套索引 |
| **12** | `intermediate_velocity` **死参数** | 配置项**只有用到的那些**（vlim, alim, jlim, 容差, 网格数） | 每个配置项都在报告里被回算一次 |
| **13** | `ToppraConfig` 四项 UI **不可达** | 所有约束都从 `命令.规划` 传入，界面上能改，且**改了会体现在报告里** | 换约束重规划 → 报告里的限位跟着变 |

## 四、核心算法（我们的版本）

```
输入：航点 W (N×n) [关节角, rad]；关节限位 vlim, alim, jlim (n,)；参数
  ↓
[1] 去重 + 单调化：删掉相邻重复点（否则弧长为 0，s 不严格递增）
[2] 平滑（可选）：Laplacian passes + 端点钉死 + np.unwrap（±π 跳变）
    → 立刻回算 max|W_smooth - W_raw|，超容差就失败
[3] 弧长参数化：ss[i] = 累计关节空间欧氏距离 / 总长 ∈ [0,1]
[4] 三次样条 q(s)：CubicSpline(ss, W_smooth) → 可求 q'(s), q''(s)
[5] 速度包络（闭式）：对每个网格点 s
      v_s_max(s) = min_i ( vlim_i / |q_i'(s)| )        （|q'| > eps 的关节才参与）
      另外叠加加速度约束的保守界：
      a_s_max(s) = min_i ( alim_i / |q_i'(s)| )
[6] 前后向扫描（离散，jerk 受限）：
      前向：sd[k+1] = min( sd[k] + a_max*dt_k, v_s_max(s[k+1]) )
      后向：sd[k]   = min( sd[k], sqrt( sd[k+1]² + 2*a_max*ds ) )
      再对 sd 做一次 jerk 限幅（slope limit）
[7] 时间积分 → t[k]
[8] 链式法则出 qd, qdd；jerk 用 qd 的样条/差分（**并校验**）
[9] 回算校验：max|qd| ≤ vlim? max|qdd| ≤ alim? max|jerk| ≤ jlim?
      sd[-1] ≈ 0? 偏差 ≤ 容差? 贴边程度（谁最先顶到限位）
[10] 输出：t, s, sd, sdd, q, qd, qdd, 校验报告, 瓶颈位置
```

`[5]` 的关键：**闭式解**。速度约束下每条曲线的"该点最大路径速度"就是
`min_i vlim_i / |q_i'(s)|` —— 因为 `|qd_i| = |q_i'| · sd ≤ vlim_i`。
不需要任何 solver。LE 用 TOPPRA 求这个上界，是"杀鸡用牛刀"，也引入了
`X[:,1]` 要开平方这种容易漏的细节（§5.12 的 `[7]` 特意标了 `★★`）。

### 关于 jerk 的诚实说明（实现后修正的设计）

设计时我写的是"前后向扫描里两个方向都用同一个 jerk 限"。**实现后发现这做不到**，
而原因值得记下来：

我们的时间律是"加速度受限的前后向扫描"，它天然是 **bang-bang** 的 ——
加速度在切换点从 `+a` 跳到 `−a`，**理论上 jerk 无穷大**。实测：
2000 个网格点里 jerk 的 99% 分位是 2.0，而峰值 3.52 单调地出现在**切换点那一个点**上。

要真正限住 jerk，必须在切换点插入一段时长为 `a/j` 的斜坡（S 曲线整形）——
那正是 Ruckig 存在的理由。试过两条更便宜的路，都失败：

| 尝试 | 结果 |
|---|---|
| 时间域对 `sdd` 做 jerk 率限制 + 迭代重积分 | 加速度只能降不能升（漏了下界）→ 轮廓衰减到 0，**144/2000 个网格点速度变 0**，轨迹中途停住；补上双侧钳制后仍不收敛（201 个点归零） |
| 二分缩放加速度直到 jerk 达标 | jerk 峰值来自切换点的不连续，**与加速度幅值几乎无关** —— 缩到 1/50 仍是 3.52 |

所以最终立场是：**能把 jerk 报准，但不会假装限住它**。
超限时 `成功=False` 并写明实测值与限值，调用方看到的是明确失败，
而不是一条"看起来没问题"的轨迹。

> 这一条与 LE 的做法其实同源（它也不在减速段施 jerk），差别在于：
> **我们把它标出来了，它没有**（缺陷 ⑤ 的 `warnings` 恒空就是这么来的）。

## 五、这一版**做不到**什么（诚实清单）

| 项 | 状态 |
|---|---|
| 笛卡尔航点 / 基本元（直线/圆弧）/ CSV 导入 | ❌ 只做**关节航点**这一种输入（规格里最基础的一种） |
| 时间最优（TOPPRA 那种精确解） | ❌ 我们算的是"包络 + 前后向"，只报**下界**做对照 |
| 跟踪控制器在仿真里执行 | ✅ 见 §六 |
| 换约束重规划并逐点对比 | ✅ 报告结构支持，界面提供"重规划" |

## 六、与现有架构的接口

沿用既有的"桥 + 契约 + 视图"三段式，**不新造一套**：

| 层 | 模块 | 职责 |
|---|---|---|
| 算法 | `软件/轨迹规划.py` | **纯函数**：数组进、数组出，不碰 mujoco / 不碰 UI（可单测） |
| 桥 | `软件/规划桥.py` | 插件：收 `命令.规划` → 调纯函数 → 发 `规划结果`；持有航点 |
| 契约 | `规划` / `规划结果` / `命令.规划` | 三个主题 |
| 视图 | `前端/src/视图/规划视图.tsx` | 记录航点 → 规划 → 看校验数字与包络曲线 |
| 执行 | 现有 PD 控制器 | 轨迹作为**参考目标**喂给已有的"关节pd控制"，不另写跟踪器 |

> 最后一行是刻意的：规格要求"独立跟踪控制器"。项目里**已经有一个**
> （`算法库/通用/关节pd控制.py` + 参数面板）。再写一个只会让"哪个在控机器人"变模糊
> —— 那正是这个项目一直在防的那类混乱。
