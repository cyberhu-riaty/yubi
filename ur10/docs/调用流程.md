> 更新说明：本文记录最初的示例、legacy 脚本与默认 UR10Friction 调用关系，行号可能随改动移动。重绘入口现采用 `CONFIG → friction.files.load_friction → FileFriction.torque`，机器人文件通过 `load_robot` 读取；路径和格式见 [文件配置接口](文件配置接口.md)。独立 legacy 脚本仍使用自己的默认 UR10Friction；新文件配置应用于 reproduce_torque_figures.py 入口。

## 0. 三层结构

```
┌─ 入口层 ───────────────────────────────────────────────┐
│ examples/run_friction.py      正向仿真示例（跑 100 步）  │
│ tests/test_friction.py        4 个回归测试               │
│ experiments/legacy/scripts/*  5 个离线实验脚本           │
└──────────────────────┬────────────────────────────────┘
                       │ import
┌─ 封装层 friction/ ───▼────────────────────────────────┐
│ __init__.py   门面：只做 re-export（第 3–6 行）          │
│ model.py      UR10Friction：参数 + 摩擦公式 + 关节映射    │
│ dynamics.py   inverse_dynamics / step_with_friction      │
└──────────────────────┬────────────────────────────────┘
                       │ 调用
┌─ 物理引擎 ───────────▼────────────────────────────────┐
│ mujoco: mj_inverse（逆动力学）/ mj_step（正向仿真）       │
│ models/ur10_extfric.xml：damping=frictionloss=0，armature 保留 │
└───────────────────────────────────────────────────────┘
```

**一句话**：`friction` 是唯一持有摩擦参数的地方；它只做两件事——把速度算成摩擦力矩（`torque`），以及把这个力矩塞进 MuJoCo 的两个入口（`mj_inverse` 逆行、`mj_step` 正向）。

## 3. 路径 B：`python -m unittest discover -s tests -v`

`tests/test_friction.py` 的 4 个用例，各自走的链路：

| 用例 | 行 | 调用的封装函数 | 断言什么 |
|---|---|---|---|
| `test_archived_trajectory` | `:23–33` | `law.torque`（`model.py:41`）、`inverse_dynamics`（`dynamics.py:11`） | 与 legacy 存档 `.mat` 数值一致：摩擦 `atol=1e-12`，总力矩 `atol=3e-6`（跨 MuJoCo 版本留的余量） |
| `test_forward_step_matches_manual_force_and_preserves_other_force` | `:35–56` | `step_with_friction`（`:50`） | `:51` 外力被恢复；`:52` 返回值 = `law.torque`；`:55–56` 与"手工减力 + 裸 `mj_step`"结果逐位相同 |
| `test_zero_speed_preserves_identified_bias` | `:58–59` | `law.torque` | `torque(0) == b`，即零速保留辨识偏置 |
| `test_rejects_xml_with_built_in_friction` | `:61–64` | `law.validate_model`（`model.py:62`） | 加载 `models/ur10.xml` 时抛 `damping and frictionloss must be zero` |

其中第 2 个用例是**封装正确性的关键证明**：它验证了 `step_with_friction` 等价于"自己减力再调 `mj_step`"，且不污染调用方的 `qfrc_applied`。

`inverse_dynamics`（`dynamics.py:11`）内部链路：

```
:19  law = friction or UR10Friction()
:20  indices = law.validate_model(model)          → model.py:62
:22–27 形状/有限性/nq 校验
:30  data = mujoco.MjData(model)
:32–37  for i in range(len(qs)):
          :33 data.qpos[:] = qs[i]
          :34 data.qvel[:] = dqs[i]
          :35 data.qacc[:] = ddqs[i]
          :36 mujoco.mj_inverse(model, data)      → 得 qfrc_inverse
          :37 result[i] = qfrc_inverse[indices] + law.torque(dqs[i])   ← 加！
:38  return result[0] if single else result
```

**这里符号是"加"**：逆动力学问的是"电机需要输出多少"，摩擦是额外负担，所以加上；而正向仿真问的是"实际受到多少阻力"，所以减掉。两个符号都对，但容易看混。

## 6. 三条设计约束（读代码时的"为什么"）

1. **`validate_model` 出现在每一处调用入口**（`dynamics.py:20`、`:53`，`run_friction.py:19`），而不是只在构造时检查一次。因为 `MjModel` 可以被调用方随时改（legacy 脚本就常改 `dof_damping`），每次用前重查才安全。
2. **必须用 `ur10_extfric.xml`**：`ur10.xml` / `ur10_normal.xml` 自带 `damping`，`ur10_extfric.xml:62` 的注释写明"damping/frictionloss 全部置 0"。用错文件 `validate_model` 会直接拒绝。
3. **`step_with_friction` 必须是每一步唯一入口**：直接调 `mj_step` 不会施加外部摩擦（README 第 53 行也强调了），只有走这个函数才有阻力；它用 `try/finally` 保证 `qfrc_applied` 一定被恢复，因此可以安全地与其他外力共存。
